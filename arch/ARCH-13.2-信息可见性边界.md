# ARCH-13.2 信息可见性边界（实现级规范）

- 对应 GDD v0.3 §13.2；与 ARCH-9.5 配套（后者解决"怎么判"，本文解决"谁能知道什么"）
- 状态：v1.0（待原型实现验证）
- 目标读者：服务端网络/同步层、客户端渲染层、反作弊实现者

## 0. 原则

1. **服务器权威 = 数值权威 + 信息权威**。客户端只应收到"该玩家在游戏世界中有合法感知渠道"的信息。
2. **泄露的定义在协议不在客户端**：只要 L3 信息被下发过一次，改包客户端就已完成透视，事后封号无意义。
3. 一切交互结果（嗅闻/闯入/激怒）由服务器计算，**只单播操作者**。
4. 客户端渲染层（含 pixelfx 特效与视觉声呐）只能消费已收到的下行包——这条约束本身就是反作弊面的实现。

## 1. 信息分级表（L0~L3）

| 级别 | 定义 | 内容清单 |
|---|---|---|
| **L0 全局公开** | 人人可见，可组播 | 铃/预备铃/软收尾倒计时、局面阶段、已定型玩家的名次（完成用时/炸裆时间）、主任**登场与离场演出事件**（只广播"主任已进入厕所区域"，**不含隔间号**）、公共喊话轮盘广播 |
| **L1 位置/物理** | 感知半径（15m）或 LOS 内 | 其他玩家位置与朝向、池位占用者身份（入口视野区特例）、隔间**视觉指示**（红/绿/故障——可能是被贴纸篡改过的版本）、道具与拾取事件、洗手台暗格状态 |
| **L2 事件级** | 半径内可闻（定向下发） | 声脉冲：排尿声/连带排尿声/涡轮嗯嗯/捅门/拍门/冲水/干呕/推门期主任预警音（报纸+咳嗽，仅当目标隔间真值为主任且推门者在音效半径内） |
| **L3 身份/真值** | 仅服务器持有，按交互结果定向释放 | 隔间占用**真值**（占用者是谁/是否主任）、主任身份与入住隔间、隔间内玩家的 debuff/忍耐值/排便进度、骚扰值数值、嗅闻结果（仅操作者）、传染扣血明细（仅双方）、主任候选 roll、贴纸真实粘贴状态 |

**核心设计**：主任登场是 L0（全员知道危险来了），入住哪间是 L3（必须花嗅闻/推门期预警音/道具去换）——信息经济学就是玩法的核心张力。

## 2. 实体模型与下行通道

```
实体: Player×5 | Stall×3 | Urinal×3 | Dean×0..1 | ItemPickup×N | NoiseEvent(瞬时)

下行 = 双通道:
  delta 通道: {t:'delta', tick, ents:[EntityDelta]}   # L1，按每个观察者的订阅集
  event 通道:
    {t:'broadcast', ev}        # L0，房间内组播
    {t:'noise',     ev}        # L2，按半径+遮挡计算 recipients 白名单
    {t:'result',    action_id, view}  # L3 释放，仅单播操作者
    {t:'snapshot',  view}      # 重连，见 §4
```

**Stall 实体下发的 `occupancy` 字段 = 视觉指示层**（红/绿，可能被假贴翻转），真值字段永不下发。占用真值只能经 `result` 包释放（嗅闻三态、推门期采样、被逼出事件对当事人）。

## 3. 感知半径与 AoI（兴趣管理）

| 情形 | 规则 |
|---|---|
| 同房间、感知半径内（15m / LOS） | 20Hz 全量 delta |
| 同房间、感知半径外（走廊两端对峙） | 位置降频至 1Hz 且**量化到 2m 格点**（保留战术存在感，不足以隔墙定位） |
| 隔间遮挡 | 隔间内玩家的位置 delta 对门外观察者**停发**（只发"该隔间有人"的视觉指示，这本就是 L1） |
| 音源（L2） | 服务器按 `radius` 字段 + 走廊/隔间遮挡计算 recipients；视觉声呐（无障碍）只能渲染收到的 `noise` 包 |
| 道具拾取 | 拾取事件 L1（半径内可见），全图道具剩余数量不下发 |

## 4. 重连快照（裁剪规则）

```
snapshot(self) =
    self 完整状态                  # 位置/忍耐/道具/技能/在途演出
  + L0 全量                        # 阶段/倒计时/已定型名次/公共事件日志
  + 周边实体的 L1/L2 视图          # 用观察者=self 的同一套感知函数计算
  + 已广播事件重放                 # 断线期间的 L0/L2(若当时在半径内) 演出补播
  − 任何 L3
```

- 断线期间主任入住 → 重连后**不知道**（盲撬自负，GDD 2.3 的"谨慎闯入"提示由此而来）。
- 在途引导全部 ABORT 回滚（ARCH-9.5 C10），快照中的道具账即回滚后账目。

## 5. 观战流

- 观战输入 = `follow(player_id)`；输出 = **以被跟随者为观察者**跑一遍 §3/§4 的感知函数，重放其"应见视图"。不存在上帝自由镜头接口。
- 延迟缓冲 15s；AFK 判负入观战者 +60s；同房存在关联账号（IP 段/指纹聚类）→ 观战延迟抬至 ≥ 对局剩余时间（风控判定在服务器）。
- 厕所电视台互动包（纸团/预测/热度条）走独立通道，**不携带任何 L1/L2/L3 游戏信息**。
- 全场定型后观战流 3 倍速追平再统一弹结算；集锦从服务器权威录像流生成（与结算同源，杜绝延迟流与排名不一致）。

## 6. 反作弊校验点（服务器侧）

| # | 校验 | 拦截目标 |
|---|---|---|
| V1 | 一切 intent 先过 `server_perceivable(actor, target)`（ARCH-9.5 段③）：目标不在感知半径/LOS → 拒绝 | 隔空交互、雾里撬锁 |
| V2 | 协议面不存在"全量状态"接口；L1/L2 严禁组播到非 recipients | 改包透视 |
| V3 | 嗅闻/推门/激怒结果只走 `result` 单播；不广播"谁闻了什么" | 结果侧信道 |
| V4 | 客户端预测仅自身移动；服务器校验速度/单帧位移硬上限，超限回弹+计数 | speedhack / 纠偏通道注入 |
| V5 | tick 冲突按轮转优先级/窗口随机，不按到达序 | lag switch / RTT 套利 |
| V6 | 行为风控：从未嗅闻却持续精确避开主任、打断反应时间低于人类 P99 → 标记复核（名次分 24h 延迟入账兜底） | 内存读取型外挂（读了也只用得起一次） |
| V7 | `noise` 包带 recipients 白名单且不含 source 真值字段（音源位置量化到 1m） | 音频雷达 |

## 7. 与表现层的契约（pixelfx 视觉冗余映射）

所有 L2 音频情报必须有视觉冗余（GDD §14 无障碍承诺），渲染层映射到 `refs/pixelfx` 特效库：

| 游戏事件 | pixelfx 来源 | 约束 |
|---|---|---|
| 声波图标脉冲（视觉声呐） | `src/fx/ui/exclamation.js` 改造 / 用 pixelfx skill 自制 ripple | **只渲染收到的 `noise` 包** |
| 炸裆 | `spawn/poof` + `explosions/cartoon-pow` | L0 组播 |
| 逼出弹射 | `impacts/heavy-landing` + 尘土 | L1（半径内） |
| 涡轮增压 | `lightning/charge-up` / `status/rage` | L2 定向 |
| 主任破门激怒 | `explosions/barrel-explosion` 缩放 / `impacts/ground-slam` | L0 组播（不暴露其隔间号——演出锚定在受害者位置） |
| 嗅闻结果 UI | `ui/crit-number` 风格置信度星 | L3 单播操作者 |
| 下课铃/结算转场 | `transitions/crt-off` / `blinds` | L0 |
| 恶臭区域 | `nature/poison-cloud` | L2 半径内 |

新增特效一律用 `refs/pixelfx/skills/pixelfx` skill 生成（draft→render→look→refine 流程），保持"代码即美术资产"。

## 8. 验收用例

1. **透视不可行**：抓包客户端 A 全部下行包，在主任被任一交互命中前，无法重建"主任在哪个隔间"
2. 改客户端解除音效半径限制 → 收不到 radius 外的 `noise` 包，无从渲染（V7）
3. A 断线期间主任入住 → 重连快照无该信息；A 盲撬的后果自负且服务器有记录
4. 观战者请求自由镜头 → 协议无此接口，仅 `follow`；抓包确认观战流=被跟随者视图
5. 对 30m 外的门发 WIRE_BREAK → 段③ V1 校验拒绝
6. 同 tick 双人各自 SNIFF 同一主任间 → 各自独立 roll 误判，互不可见对方结果（V3）
7. 走廊两端（半径外）观察对手 → 位置仅 1Hz/2m 格点，无法据此推断隔间内进度
8. 回放一致性：观战延迟流与权威录像流按同一 tick 对账，事件集合一致
